# 使用待办事项

待办事项是触手的操作中心。

## 待办解析的工作方式

Octogent 直接读取 `todo.md`，不会把待办状态复制到单独的存储中。

只有 markdown 复选框行会被解析：

```md
# Todo

- [ ] inspect websocket reconnect path
- [ ] add regression test for idle grace handling
- [ ] update runtime docs
```

解析器识别：

- `- [ ] 文本` 为未完成
- `- [x] 文本` 或 `- [X] 文本` 为已完成

其余 markdown 可以用来写笔记，但会被进度解析器忽略。待办项的身份由位置决定：第一条被解析的复选框行是索引 `0`，下一条是索引 `1`，依此类推。

## 好的待办项

好的待办项应当：

- 具体
- 可验证
- 窄到一个代理能独立完成
- 脱离聊天历史也能看懂

糟糕的待办项含糊不清，迫使代理重新摸索任务本身。

由于工作代理的提示词是从待办文本生成的，每一项都应携带足以独立执行的范围。把更宏观的架构、约束和归属说明放进 `CONTEXT.md`；把具体动作写进 `todo.md`。

## 编写模式

- 每个工作区域一个触手
- 每个触手一份 `todo.md`
- 任务写到"一次子代理指派"的粒度
- 保持顺序有意义，因为集群（swarm）溢出时按待办顺序截断
- 在文件里或通过 UI 勾选完成，UI 操作会重写文件

## 待办如何驱动执行

Deck 运行时把同一份解析结果用于三种工作流：

- 触手卡片上的进度展示
- 单项求解：一条待办变成一个工作终端
- 集群创建：未完成项变成工作代理的任务指派

单项求解时，Octogent 会创建形如 `<tentacle-id>-todo-<item-index>` 的终端 ID，并为该项启动一个共享工作区的工作代理提示词。

创建集群时，Octogent 过滤未完成项，视情况收窄到指定的索引，按父子上限截断批次，然后创建形如 `<tentacle-id>-swarm-<item-index>` 的工作代理 ID。当工作代理超过一个时，它会创建一个父协调者终端，而不是直接从 API 启动所有工作代理。父提示词里包含工作代理的创建命令与完成策略。

## 编辑与漂移

UI 中勾选、编辑、新增或删除待办时会重写 `todo.md`。手工编辑同样有效，但可能改变项的索引。在求解代理或集群运行期间，除非协调者知晓变更，否则应避免调整待办顺序。

除非任务明确要求，工作代理不应自行把自己的待办项标记为完成。在集群流程中，应由协调者或人工评审在检查合并结果后更新 `todo.md`。

## 示例

```md
# Todo

- [ ] add API route for terminal rename
- [ ] test invalid terminal ids
- [ ] document rename flow in CLI reference
```

这给了你三个干净的委派单元，而不是一个过大的提示词。
